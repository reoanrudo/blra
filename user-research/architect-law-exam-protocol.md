# 一級建築士「学科Ⅲ（法規）」過去問による要件学習プロトコル

- 決定日: 2026-08-09
- 対象: 令和3〜7年（2021〜2025年）の学科Ⅲ（法規）150問
- 目的: 外部参加者を集める U-1/U-2 に代えて、法規問題から検索条件・根拠条文・法令間遷移・例外確認の課題を抽出する
- 判断根拠: ADR-031

## 1. 一次資料

建築技術教育普及センターが公開する次の公式資料だけを使用する。

- [一級建築士試験 過去の試験問題等](https://www.jaeic.or.jp/shiken/1k/1k-mondai.html)
- 各年度の「学科Ⅲ（法規）」問題PDF
- 各年度の「合格基準点等」PDFに掲載された正答肢

問題文は転載・再配布しない。リポジトリへ保存するのは、年度・問題番号・分類・検索条件・
根拠条文セット・法令間経路・正答確認結果などの派生情報だけとする。

公式資料にも明記されているとおり、過去問は試験実施時点の法令に基づく。現在の法令へ
そのまま読み替えず、年度ごとの適用法令日を必ず記録する。

## 2. 学習用と評価用の分離

| 区分 | 年度 | 問題数 | 用途 |
|---|---|---:|---|
| 学習セット | 令和3〜6年 | 120問 | 課題分類、実務語辞書、検索・関連導線の要件抽出 |
| 未見評価セット | 令和7年 | 30問 | 実装後の検索・根拠到達・例外確認の評価 |

令和7年の問題から要件や辞書を作らない。評価前に正解セットだけを固定し、学習セットへの
漏洩を防ぐ。新年度の公式問題が公開されたら、直前年を学習セットへ移し、新年度30問を
新しい未見評価セットにする。

## 3. 初回棚卸しで確認した出題特性

令和3〜7年の150問を、全文転載せず機械的に棚卸しした。

| 特性 | 該当問題数 | 要件への示唆 |
|---|---:|---|
| 規模・用途・高さ・面積・期限などの数値条件を含む | 132 / 150 | 条文番号より案件条件を入口にする |
| 例外・除外・緩和・特例を含む | 67 / 150 | 本則だけでなく例外確認を完了条件にする |
| 条文番号を明示する | 24 / 150 | 条番号を知らない探索を標準ケースにする |
| 毎年度30問 | 150 / 150 | 年次更新可能な固定ベンチマークにできる |

出題構成も毎年おおむね安定している。

1. 建築基準法の定義、面積・高さ・階数、確認・検査
2. 防火・避難、建築設備、構造
3. 道路、用途制限、容積率・建蔽率、高さ制限
4. 建築士法、都市計画法、消防法、バリアフリー法、建築物省エネ法
5. 複数法令を横断する設計者判断

この構成を、検索、委任先遷移、逆引き、例外表示、未収録表示の評価カテゴリとして使う。

## 4. 1問から作る階層型の派生レコード

各問題は「問題単位→全選択肢由来の派生論点→統合判断」の階層で記録する。問題文・選択肢の
全文は記録しない。

### 4.1 問題単位

| 項目 | 内容 |
|---|---|
| `exam_year` / `question_no` | 公式資料へ戻るための識別子 |
| `legal_snapshot_date` | 問題で適用すると指定された法令日 |
| `task_category` | 定義、手続、防火避難、構造、集団規定、他法令、横断判断 |
| `official_answer_source` | 公式正答肢を持つ既存マニフェストへの参照。正解セットへ重複保存しない |
| `issue_set_status` | 全選択肢由来の論点が揃ったか。`partial` / `complete` |
| `issues` | 1件以上の派生論点 |
| `integration` | 問題全体の判断方式と、最終判断に寄与する論点 |

### 4.2 派生論点

| 項目 | 内容 |
|---|---|
| `issue_id` | 問題内で一意な識別子 |
| `source_choice_nos` | この論点がカバーする選択肢番号。選択肢本文は保持しない |
| `task_category` | 論点単位の分類 |
| `project_conditions` | 用途、構造、階数、面積、地域、工事種別、時点 |
| `query` | 条番号を前提にしない短い判断課題 |
| `expected_conclusion` | 法令確認から導く短い派生結論。部分移行中だけ `null` を許す |
| `target_provisions` | 結論に必要な法・令・規則・告示の条文集合 |
| `navigation_paths` | 根拠へ到達する法令間・条文間の経路。複数経路を許す |
| `exceptions` | 適用除外、ただし書、緩和、経過措置 |
| `unsupported_sources` | 現行コーパスで未収録の告示・条例等 |
| `rationale_status` | 論点の根拠確認状態 |

計算問題など、複数の選択肢が同じ判断過程を共有する場合は、一つの派生論点で複数の
`source_choice_nos` をカバーしてよい。全ての問題を機械的に4論点へ分割しない。

`query` と `expected_conclusion` は各120文字以内、`project_conditions` の各要素は80文字以内とし、
元の選択肢を実質的に復元できる長文を保存しない。長くなる場合は独立した論点へ分割する。
既存Schema Version 1からの部分移行では、推測で結論を補わず `expected_conclusion=null`、
`integration.decision_type=unresolved` とする。`complete` または `verified` ではこれらを許可しない。

## 5. 評価タスクへの変換

過去問を四肢択一のまま画面へ出さない。全選択肢から案件条件または判断目的を派生論点として
抽出し、短い検索課題へ変換する。

- 条文番号が問題に書かれていても、条番号検索を評価する場合を除いて入力から外す
- 用途・規模・階数・地域・工事種別・時点は残す
- 「正誤を選ぶ」ではなく「根拠条文と例外を示す」課題に変える
- 正答肢だけでなく、全選択肢から派生する論点を抽出する
- 各選択肢番号が少なくとも一つの派生論点でカバーされていることを確認する
- 各論点の結論に必要な根拠条文セットと複数の法令間経路を正解とする
- 論点別判断と問題全体の統合判断を分けて記録する
- 告示・条例が必要で未収録なら、黙って省略せず未収録と表示できることを正解に含める
- 全論点が試験年度の法令で確認されるまで、問題全体を `verified` にしない

## 6. 評価指標

人の所要時間を分母にする旧 U-2 Baseline は使わない。次を固定指標とする。

| 指標 | 判定内容 |
|---|---|
| Recall@10 | 必要な根拠条文が検索上位10件に含まれるか |
| 根拠条文セット到達率 | 課題に必要な法・令・規則・告示を過不足なく開けるか |
| 法令間経路完全率 | 法→令→規則・告示、または逆方向を欠落なく辿れるか |
| 例外確認率 | ただし書、適用除外、緩和、経過措置を確認できるか |
| 未収録明示率 | 必要な告示・条例等が未収録の場合に存在を明示できるか |
| 誤根拠率 | 課題と無関係な条文を確定根拠として提示しないか |
| 選択肢由来論点カバー率 | 選択肢1〜4がそれぞれ少なくとも一つの派生論点でカバーされているか |
| 論点検証完了率 | 問題内の全派生論点のうち根拠確認済みの割合 |
| 複合問題完了率 | 全論点と統合判断が確認済みの問題の割合 |
| 複数経路完全率 | 論点に必要な縦断・横断経路を全て辿れたか |
| 統合判断正答率 | 全論点の確認後に公式正答と一致する判断を出せたか |

S2 の合格条件は従来どおり主要課題の Recall@10 80%以上とする。加えて、未見評価30問の
各指標を問題・論点カテゴリ別に報告し、平均値だけで弱いカテゴリや未確認論点を隠さない。

問題単位の評価対象にできるのは、全選択肢が派生論点でカバーされ、全論点、統合判断、適用法令日
が確認済みの場合だけとする。一部論点の確認は進捗には数えるが、問題単位の成功率には含めない。

## 7. この方法で測れないもの

過去問から、検索条件、法令知識、法令間経路、例外の読み方は学習できる。一方で、次は測れない。

- 実務者が対価を払うか
- 組織内の承認・差戻し・引き継ぎ方法
- 実案件固有の自治体運用や未公開資料

これらは S1/S2 の前提条件にしない。動く製品ができた後の任意フィードバックとして扱い、
外部参加者の人数・組織数を開発ゲートにしない。
