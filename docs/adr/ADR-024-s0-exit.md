# ADR-024: S0 Corpus Feasibility の完了判定

- ステータス: Accepted
- 決定日: 2026-07-29
- 決定者: Taguchi（事業判断）+ AI（技術判定）
- 関連: 設計書 §15.2 / §15.9.1 / ADR-014 / ADR-023

## 背景

設計書 §15.2 は Corpus Feasibility（S0）を User Research に先行させる独立ゲートとし、
F-1〜F-9 の9項目と3択の事業判断（O-1）を完了することを Exit Criteria とした。
また §15.9.1 に中止条件を設け、該当した場合は S1 へ進まず判断へ戻ると定めた。

## 判定: S0 PASS — S1 へ進む

**案Bを採用した（ADR-023）。** 告示の溶け込み現行全文は提供せず、案文＋改正履歴の提示に留める。

### 中止条件（§15.9.1）のチェック

| 中止条件 | 該当 | 理由 |
|---|---|---|
| 告示の統合が1件あたり2時間を超える | **非該当** | 案B採用により統合を行わない（ADR-023） |

**両中止条件とも非該当。S0 を通過する。**

## S0 で判明した制約（S1 以降への引継ぎ）

S0 の結果、プロダクトの前提が確定した。これらは S1 の設計に直接影響する。

1. **告示は原文のみ提供（ADR-023）**: `OFFICIAL_AS_ENACTED` と改正履歴の一覧。`DERIVED_CONSOLIDATED` は MVP では作成しない
2. **coverage_from の制約（F-9）**: 法=2016-09-01、令・規則=2017-04-01。2016年以前の既存不適格案件では当該時点の条文を表示できない。`EXISTING_BUILDING_ORIGIN` アンカーは起点日の記録機能に留める
3. **自治体例規の利用条件は自治体ごとに異なる（F-8）**: 条文は著作権法第13条で自由だが、編集物は PDL1.0 と独自規約が混在。手動登録時に利用条件を確認する
4. **告示 PDF は全件テキストPDF（F-3）**: OCR は不要。ただし縦書きレイアウトによる1文字ごとの改行・空白の正規化が必須

## S1 着手前の必須前提（残項目）

設計書 §15.2 の S1着手前前提のうち、S0 の範囲外または未完了のもの。

| 前提 | 状態 | 備考 |
|---|---|---|
| Domain Reviewer の確保 | **未完了** | ADR-016 により未確保のまま S1 へ進めない。Taguchi さんの作業 |
| O-1（告示の入手可否） | **決定済** | 案B（ADR-023） |
| O-2（日本語検索基盤） | **実質決定** | F-7 で pg_bigm 採用。ADR 化は S1 着手時で可 |
| O-3（対象テーマの確定） | **未決定** | F-9 の結果（既存不適格制約）を踏まえ、新築の防火・避難に寄せる方向（F-9 推奨案A+C）。U-1 ヒアリング結果と合わせて最終決定 |

**Domain Reviewer の確保が S1 着手の唯一のハードブロッカーである。** これが解決され次第、S1 へ進む。

## U-1〜U-4（User Research）の状態

U-1〜U-4 は S0 と並行して進める設計だった（§15.3）。特に U-1「告示の現行全文が読めないツールに価値があるか」は、ADR-023（案B）の価値提案の成否を分ける論点である。これが確認できないまま S1 へ進むと、プロダクト全体の前提が崩れるリスクがある。

**U-1 の完了（または最低限の確認）も S1 着手の実質的な前提とする。**
