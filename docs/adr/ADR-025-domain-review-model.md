# ADR-025: Domain Review 体制の改訂（ADR-016 の改訂）

- ステータス: Accepted
- 決定日: 2026-07-29
- 改訂対象: ADR-016（設計書 §15.8.1、`docs/domain-reviewer-role.md`）
- 影響: **S1 のハードブロッカーを解除する**

## 背景: ADR-016 の前提が事実と異なっていた

ADR-016 は、建築法令 Domain Reviewer の外部確保（有償・1〜2名・総工数 60〜100 時間）を S1 着手の必須条件とし、実装者による兼任を禁じた。

その理由として挙げたのは次である。

> 本プロダクトの価値は「表示している条文が、指定した時点において正しい」ことに全面的に依存する。しかしこの正しさは、実装者が AI を用いても自己検証できない。法令本文の正誤、告示の統合結果の妥当性、参照関係の抽出精度は、建築実務の知識を持つ人間にしか判定できない。

**この前提は誤りであった。** 実装者は二級建築士であり、主に老人ホーム規模の設計実務に従事していた。挙げた4項目（本文の正誤、告示と法令の対応、参照関係の妥当性、正解セットの正しさ）は、いずれも実装者自身が判定できる。

ADR-016 は、実装者の経歴を確認しないまま「実装者＝非実務者」と仮定して書かれた。前提が違う以上、結論も維持できない。

## 決定

### 1. 日常のドメイン検証は実装者が行う

次は実装者の職能で担保する。外部レビューを介さない。

- 構造化した条文が原文と一致しているかの確認
- 告示と根拠法令の対応付けの妥当性判断
- 参照関係（`DELEGATES_TO` / `EXCEPTS` 等）が実務の読み方と合っているかの判断
- 検索課題の正解セットの作成
- U-2 Baseline タスクの設計と正解の確定

### 2. 独立チェックはゲート時点のサンプリング検査に限定する

知識の有無とは別に、**独立性**という論点は残る。パーサを書いた本人がその出力を検証すると、意図を知っているぶん出力を好意的に読む。100 件を通しで確認すれば、後半で精度が落ちる。これは能力ではなく構造の問題であり、実務経験があっても消えない。

ただしこれは、継続的な外部レビューを正当化するほど強い理由ではない。次の形に縮小する。

| 時点 | 内容 | 工数 |
|---|---|---|
| S1 完了時 | 公開済み条項から無作為抽出した 20〜30 件を第三者が原文と照合 | 4〜8 時間 |
| Pilot 前 | 同上。加えて代表的な調査タスク3件の正解セットを検証 | 4〜8 時間 |

**総工数 8〜16 時間。** ADR-016 の 60〜100 時間から大幅に縮小する。この規模なら、知人の専門家へ都度依頼できる範囲に収まる。

### 3. 検査者に望む属性

一級建築士または建築基準適合判定資格者が望ましい。理由は実装者の判定能力への疑念ではなく、**二級建築士の業務範囲を超える規模の特殊建築物について視点を補う**ためである。防火・避難は規模が大きいほど論点が増える領域である。

確保できない場合、同等の実務経験者でよい。**サンプリング検査が実施できないことを理由に S1 を止めない。** ただしその場合は「独立検査未実施」を Pilot 参加者へ開示する。

### 4. 機械的検証の比重を上げる

人が見なくても壊れない箇所は人に見せない。既に実装・実証済みのものを正式に検証手段として位置づける。

- F-2 の抽出率計測（99.97〜100.00% を実測）
- Content Hash による原本の同一性確認
- `EXCLUDE USING gist` による有効期間重複の禁止（F-7 で7ケース実証）
- `CHECK (valid_from_status <> 'FIXED' OR valid_from IS NOT NULL)`
- Citation Resolver の Golden Test

## 帰結

**S1 着手のハードブロッカーは解除された。** ADR-024 が「唯一のハードブロッカー」としていた Domain Reviewer の確保は、S1 の前提条件ではなくなる。

残る S1 着手前の項目は O-3（対象テーマの確定）のみであり、これは ADR-026 で決定する。

## 維持するもの

ADR-016 の次の判断は維持する。

- 表示する条文の正確性がプロダクトの全価値を支えるという認識
- 正確性に関する Pilot 成功条件（時点表示正確性 99%、重大な Authority / Version 誤表示 0 件）を緩和しないこと（ADR-018）
- 「誤った条文を自信を持って表示した瞬間に、このプロダクトの存在価値は失われる」という原則（設計書 §18）

体制を軽くするのであって、基準を下げるのではない。

## 未解決のまま残る論点

**n=1 の限界。** 実装者が実務者であることは、日常のドメイン検証を解決するが、「他の実務者が対価を払うか」は解決しない。案B（ADR-023）の成否は依然として U-1 でしか確かめられない。

Domain Reviewer の確保は S1 の前提から外れるが、**U-1 の実務者接点は引き続き必要である。** この2つを混同しない。
