# 法令表・高密度レイアウト設計

## 目的

建築基準法施行令以下の法令表を、冊子型法令集のように引き締めて表示する。表の意味に応じて列幅・文字揃え・余白・罫線を決め、長文表と数値表のどちらも本文幅内で読みやすくする。横スクロールは使用しない。

## 表示仕様

### 表全体

- 表は常に本文コンテナの幅に収める。`overflow-x` による横スクロールは設けない。
- `table-layout: fixed` を維持し、列幅は表のグリッド列ごとに決定する。
- 枠線は濃い墨色の細線を基準とし、外枠と見出し行の下線だけを一段強くする。
- セルの基本余白は横を小さく、縦を詰める。長文の折返しに必要な可読性は維持する。
- 表の前後余白は本文段落より小さくし、連続する法令表の密度を揃える。

### 列幅

- 記号・号番号・短い数値だけの列は、内容を収める最小限の幅にする。
- 分数・割合・単位付き数値の列は、縦分数や数値が崩れない幅を確保する。
- 残りの幅は本文列へ配分する。長いセルほど広くするが、極端な1列独占は上限を設けて防ぐ。
- 横結合・縦結合セルを含む表では、結合前のグリッド列を基準に幅を計算する。
- 既存の特定別表向け固定幅は、共通ルールで表現できる場合は置き換える。原典の構造上必要な最小幅だけは例外として残す。

### セル内の組版

- 見出しセルは中央揃え・中程度の太さとし、過度な字間指定は使わない。
- 記号・短い分類語は上下左右中央、数値は右揃え、本文は左上揃えにする。
- 本文セルは日本語として自然な位置で改行し、英数や単位を不必要に分断しない。
- 空セルは幅を縮めるための個別指定をしない。元XMLの結合情報に従う。
- モバイルでは文字を極端に小さくせず、余白と最小列幅を縮めて表全体を収める。

## 採用設計

`TableBlock` の描画前に、各グリッド列の役割を推定する純粋なレイアウト関数を置く。入力はセル本文、結合情報、表の列数であり、出力は各列の幅比率とセルの揃え種別とする。

列役割は次の優先順で判定する。

1. 記号列: 括弧付き番号、短い番号、短い分類語
2. 数値列: 数字、割合、分数、単位付き数値
3. 本文列: 上記以外の説明文

列幅の計算は、記号列と数値列へ必要最小の幅を先に確保し、残りを本文列の正規化した文字量に比例して配分する。既存の手作業の表番号分岐は、原典由来の例外を除いて削減する。

見出し判定は行番号ではなく、表の先頭にある結合セル・短いラベル・本文行との差を合わせて行う。これにより、見出しが1行の表、複数行の表、見出しを持たない別表を同じルールで処理する。

## 対象範囲

- `TableBlock` と法令表用CSS
- 列幅・セル揃えの判定関数と単体テスト
- 建築基準法施行令を含む既存の表のブラウザ検証

DBのセル結合・罫線データおよび法令原文は変更しない。

## 検討した代替案

1. 構造優先の共通ルール: 表の種類を問わず維持でき、法令集らしい密度を保てるため採用。
2. 既存の表番号ごとの固定幅を追加: 個別表は整うが、以後の表で例外が増え続けるため不採用。
3. 表を最小幅で保持して横スクロールさせる: 情報を分断しない利点はあるが、今回の「横スクロールなし」という要件に反するため不採用。

## 検証

- 列役割・幅配分・揃え判定を純粋関数の単体テストで確認する。
- 代表表として、居室の種類表、換気回数表、複数列の別表、長文主体の別表を画面テストする。
- すべての代表表について、表コンテナが本文幅を超えず、横方向のスクロール領域が発生しないことを確認する。
- 全体テスト、型検査、実ブラウザの目視確認を実行する。
