# ページ情報削除 設計

## 目的

法令閲覧をWebの連続スクロール方式に統一するため、書籍のページ番号を現行システムの表示・API・データモデル・取込データから削除する。法令および収録条文の順番は維持する。

## 対象範囲

- 法令選択欄から書籍ページ表示を削除する。
- `LawBookEntry.printedPage` をPrismaモデルとデータベースから削除する。
- 法令一覧API、クライアント型、取込設定、法令集マニフェストから `printedPage` を削除する。
- 抄録範囲の検証データから `printedPages` とページ番号を含む説明文を削除する。
- ページ番号を介さず、収録条文と検証元画像ファイルの対応を直接保持する。
- ページ番号を前提とするテストを、新しいデータ契約と表示仕様に合わせて更新する。

## 対象外

- 法令の掲載順を示す `displayOrder` は変更しない。
- 抄録として公開する条文範囲とその並び順は変更しない。
- 検証元画像ファイル名と条文との対応は削除しない。
- 過去のデータベース移行履歴は改変しない。現行スキーマから列を削除する新しい移行を追加する。
- 調査資料やOCR記録など、過去の検証経緯を記録した文書は改変しない。

## データモデルと取込

`LawBookEntry` から `printedPage` を削除し、既存データベースには列削除の移行を適用する。法令集マニフェストと取込用 `LawConfig` も同じ契約にそろえ、取込処理がページ番号を読み書きしないようにする。

`catalogSourceLocator` は出典を識別する項目として残すが、値からページ番号を除き、ページに依存しない総目次の参照へ変更する。

抄録検証データは、ページ番号をキーに画像を引く構造を廃止する。各条文の検証データが必要な画像ファイルを直接参照する構造に変更し、条文Rangeと検証証跡を保ったままページ概念を除去する。検証メモと収録理由にもページ番号を保存しない。

## APIと画面

法令一覧APIのSELECT項目とレスポンスから `printedPage` を削除する。クライアントの `LawListItem` からも同項目を削除する。

法令選択欄のラベルは次の形式に統一する。

```text
2. 建築基準法施行令（抄）
```

先頭の番号は `displayOrder` であり、従来の順番を維持する。選択時の遷移先や法令本文の表示方法は変更しない。

## 検証

- ラベル生成の単体テストで、順番番号と法令名だけが表示されることを確認する。
- 法令集マニフェストのテストで、120法令の一意性と連続した `displayOrder` が維持されることを確認する。
- 法令一覧APIと型検査で `printedPage` が契約から消えていることを確認する。
- 抄録範囲の統合テストで、ページ番号削除後も民法（抄）の収録条文数と掲載順が変わらないことを確認する。
- データベース移行とPrisma生成が成功することを確認する。

## 成功条件

1. 法令選択欄にページ番号が表示されない。
2. 現行のデータベース、API、型定義、取込データ、検証データに書籍ページ番号が残らない。
3. 法令の順番、抄録の条文範囲、検証元画像との対応が変更されない。
4. 関連テスト、型検査、ビルドが成功する。
