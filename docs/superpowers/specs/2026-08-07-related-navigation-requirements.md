## 1. 目的

建築基準法の全文リーダー整備が完了した時点で、「関連への誘導」の弱さを定量的に特定し、
強化に必要な要素とユーザーストーリーを要件として固定する。
本文書は個別機能の実装設計に先立つ上位の要件文書である。各機能の設計・実装は、
本文書の優先度と §5 の信頼境界に従う。

背景となる実務上の根拠は research-log が既に持っている。

- 紙の法令集の行為分解で「ページを往復する — 委任先・関連条文を照合」が中核行為
  （research-log §3）
- 実務タスクの情報フロー第6歩が「委任先の政令・省令・告示を読む」（同 §4.2）
- 検索意図分類に「関係探索: `この条文の告示` → 引用・委任・準用グラフ」（同 §5）

現状はこれらの行為を支えるデータと導線が構造的に欠けている。

## 4. ギャップの構造（3層の欠落）

「関連への誘導が弱い」は単一の欠陥ではなく、3層の欠落が重なった状態である。

```text
[層1] 明示参照の解決不足
      「別表第二」「前条」「第一項」等、法令内に実在するのに未解決。
      機械的に修正可能（建築3法で351件）。

[層2] 委任参照の未リンク化
      「政令で定める」等 338ノード。本文に条番号が書かれていないため
      完全自動解決は誤リンクの温床。設計上の難所であり段階的対応が必須。

[層3] 人が確かめた関連の未投入
      ConfirmedArticleRelation の仕組みは完成済みだが、確認運用
      （Review Queue と担当者）が未開始でデータ 0 件。
```

コンセプト整合性評価（§11）により、これらに加えて「計測可能な正解セットの欠落」が第4の構造的欠落
であると特定された（評価器は実装済み、令和3年30問は正答主要論点だけの部分データ・
複合問題としての検証済み0/150問・Recall@10 未計測）。要件として
§6.7・§6.8 に反映している。

## 5. 信頼境界の原則（強化しても変えないもの）

関連を増やす作業は、以下の設計原則を壊さない範囲で行う。

- 未確認候補を確認済みリンクとして本文へ出さない（design-spec §7.3、HANDOFF 禁止事項）
- 見えている参照を黙って消さない。未解決・未収録は明示する（§7.3）
- 公式由来・運営確認済み・機械候補を同じ確からしさで混ぜない（§1.5.2）
- 本文に存在しない実務上の関連を推測で埋め込まない（§1.5.2）
- 参照探索は深さ2まで（§7.1）
- 準用の自動読替え本文を生成しない（§7.2）

## 6. 今後必要な要素（優先度）

### 6.1 P0 — 委任参照の段階的導線（垂直動線の開通）

| Stage | 内容 | 誤リンクリスク | 前提 |
|---|---|---|---|
| A | 「政令で定める」等の委任表現を検出し、「この規定は政令に委任 → 建築基準法施行令で探す」という**法令単位の導線**を出す。条文特定はしない | なし（条文を特定しないため） | 委任表現の検出器 |
| B | 本文中に法令名＋条番号が明示される参照（「建築基準法施行令第○○条」）を自動解決してリンク化 | 低（明示参照のみ） | 既存 link 検出の拡張 |
| C | 条番号を含まない委任（法第20条 → 令第36条・第38条のような対応）を**人手確認による ConfirmedArticleRelation** として投入 | 人が確認するため | Review Queue 最小実装 |

Stage C は「運営確認済み」ラベル付きの ConfirmedArticleRelation として公開し、
Stage A の導線と表示を分ける。

### 6.2 P0 — 論点索引の実装

`docs/superpowers/specs/2026-08-02-cross-law-topic-index-design.md` に従う。
DB変更不要のライブProjection。公式見出しのみを公開し、PracticeTopic へは接続しない。
「排煙」「防火区画」等の論点から条文番号を知らなくても横断到達できるようにする
（実務フロー第2〜4歩）。

### 6.3 P1 — 未解決リンクの機械的解決

§2.2② の 3 類型（同条内項参照・別表参照・前条等の相対参照）を解決する。
建築3法で 351件、DB全体で 2,689件の大部分が対象。即効性が高く誤リンクリスクも低い。

### 6.4 P1 — 逆引きナビ

施行令・施行規則の条文から「この規定の根拠は法第○条」へ戻る導線。
紙の法令集で条見出し横に併記される根拠法令表記に相当する。
Stage C の確認済み関係が蓄積すれば逆方向も同じデータから出せる。

### 6.5 P2 — 出典の確からしさ

HANDOFF 次のタスク2（AuthorityClass / consolidation_state / verification_status）。
関連を辿った先の信頼性表示に必要。バッジ表示より先に値の生成元と更新規則を確定する。

### 6.6 P2 — 告示層

委任チェーンの末端（法→令→規則→告示）。案B（告示は原文のみ提供、溶け込み現行全文は
提供しない、ADR-023）の範囲で扱う。収録自体は別ゲート。

### 6.7 P1 — 一級建築士法規過去問ベンチマーク

ADR-031 に従い、外部参加者の所要時間を使う U-2 Baseline は実施しない。一級建築士
「学科Ⅲ（法規）」令和3〜7年の150問を、次のように学習・評価へ分割する。

- 学習セット: 令和3〜6年の120問。案件条件、検索語、対象法令、根拠条文セット、法令間経路、
  例外、未収録資料を抽出する
- 未見評価セット: 令和7年の30問。要件や辞書の作成に使わず、実装後の評価にだけ使う
- 各問題は、正答肢だけでなく全選択肢から派生する論点を抽出する。計算問題等で複数の選択肢が
  同じ判断過程を共有する場合は、一つの論点で複数の選択肢番号をカバーしてよい
- 各派生論点は、案件条件、短い判断課題、期待する結論、根拠条文セット、複数の到達経路、
  例外、未収録資料、確認状態を持つ
- 全選択肢が派生論点でカバーされ、全論点と統合判断の根拠を試験年度の法令で確認した問題だけを
  問題単位の評価対象にする
- 問題文・選択肢は転載せず、年度・問題番号と派生メタデータだけを保持する
- 年度ごとの適用法令日を保持し、現在法へ自動的に読み替えない

評価指標は Recall@10、根拠条文セット到達率、法令間経路完全率、例外確認率、
未収録明示率、誤根拠率に加え、選択肢由来論点カバー率、論点検証完了率、複合問題完了率、
複数経路完全率、統合判断正答率とする。手順の正本は
`user-research/architect-law-exam-protocol.md` とする。

### 6.8 P1 — Search Evaluation Harness と検索品質要件

S2 Exit は Recall@10 ≧ 80%（design-spec §15.4）。評価器と150問マニフェストは実装済みだが、
現状の検索は LIKE 一致のみで、令和3年30問は正答主要論点だけの部分データであり、複合問題として
検証済みの問題が0/150問のため Recall@10 は未計測である。
コンセプトの「条文番号を知らなくても検索できる」「現場用語と法令用語の橋渡し」
（research-log §1.1、§5.1 の表記揺れ一覧）に未対応である。評価セットとハーネスを
先に作り、現状の Recall を可視化してから pg_bigm（ADR-027）による改善を進める。
Solo Track 中止条件「Recall@10 が 60% に届かない」（§15.9.1）の監視にも必要。

### 6.9 P2 — 時点管理の再定義（F-9 制約の要件への固定）

F-9 により、2016年（令・規則は2017年）より前の版は e-Gov から取得できず、
§4.3 の EXISTING_BUILDING_ORIGIN アンカーは実務案件の大半で機能しないことが確定している。
適用時点機能（HANDOFF タスク4）を再導入する際は、次を現行スコープとして要件に固定する。

- 各 Source の coverage_from を表示し、それより前の時点指定には「収録範囲外です」と
  応答する（§4.6 の設計どおり）
- 近似版を正しい本文として出さない
- コンセプト文書上の「適用時点の把握」の約束と、提供可能な値の差を利用者向け文言に
  明示する

1. 検出結果は再構築可能な Projection とし、正本データ（Article.text）を改変しない

## 13. 未解決リンク機械的解決の要件（2026-08-07 追記）

§6.3 の詳細要件。現行版の未解決リンク 2,689件を計測したところ、**全件が次の3パターンに
分類できた**（いずれも機械的に解決可能な類）。

| パターン | 件数 | 例 | 解決規則 |
|---|---:|---|---|
| 同条内項参照 | 1,318 | 「第一項」「第二十項」 | 同一本文ブロック内の項 N へ解決 |
| 別表参照 | 824 | 「別表第二」「別表第一」 | appdx_table ノードの text 先頭行の表題で対応付け |
| 前条・前項 | 547 | 「前条第二項」「前項」 | 出現元条文の直前の条・項へ相対解決 |

### 13.1 データ上の前提確認（2026-08-07 実測）

- appdx_table ノードは `title`・`durableNodeKey` を持たず、`stableNodeKey` は
  連番（`root/appdx_table:129@129`）のみ。表題（別表第一等）はノード text の先頭行に
  格納されている（例: 先頭行「別表第二」、次行に「用途地域等内の建築物の制限（…関係）」）。
  解決器は text 先頭行を解析して対応付ける
- 別表の表題自体が条参照を含む（「（第五十六条、第五十六条の二関係）」）。
  別表→条のリンク素材だが、本要件の初回スコープには含めず別途検討とする

### 13.2 解決規則の要件

1. 同条内項参照: 出現元の条ノード配下の項から番号一致で解決する
2. 別表参照: 同一法令内の appdx_table ノードの text 先頭行と照合する。
   「別表第三の四」のように現行法令に表題が存在しない参照は、公式原文で実在性を確認する。
   実在しない（改正で削除済み等）場合は解決せず、理由付きで未解決として保持する
   （黙って消さない原則、§5）
3. 前条・前項: 出現元の条文位置（sortOrder）から直前の条・項へ解決する。
   附則内の「前条」、章またがり、削除済み条文を跨ぐ場合は解決せず理由を保持する
4. 解決は再取込のたびに再計算する Projection とし、Link 正本の手動編集はしない

### 13.3 Non-goals

- 他法令への参照の推測解決（法令名のない他法令参照は扱わない）
- 「前条」の遡及が複数候補になる場合の推測選択
- 未解決理由の利用者向け高度な説明文

### 13.4 受入測定

- 建築3法の未解決リンク 351件の解消（対象が実在し一意に解決できるもの）。
  解決できなかった件数は理由別に集計して残件レポートとする
- DB全体の未解決 2,689件に対するパターン別解決率のレポート
- 誤リンクの目視サンプル確認（建築基準法で30件程度）

1. 「法第」「令第」等の上位法令略称参照を検出し、条番号付きで解決する。
   明示参照であり誤リンクリスクは低い（Stage B 型）
2. 略称の対応規則は法域ごとの対応表で与える（§12.2-4 と同一の対応表を使う）。
   施行令中の「法」は建築基準法、施行規則中の「令」は建築基準法施行令、
   「法」は建築基準法。フルネーム参照（「消防法第○条」等）は既存の法令間解決を使う
3. 表示は**上位条文の側**に「この条文を参照する下位規定」として出す
   （例: 法第20条の条ブロックに施行令第36条等の一覧）。
   下位条文の本文中リンク（順方向）とは別の導線として扱う
4. 解決先の条文が現行版に存在しない場合は、推測せず未解決として理由を保持する
5. 出所ラベルは「条文テキストの明示参照（公式由来）」とし、運営確認済み関連
   （ConfirmedArticleRelation）や機械候補と混ぜない

### 14.3 Non-goals

- 「法第」の参照が条全体か項号単位かの意味解釈（明示された番号そのままに解決する）
- 下位規定の「趣旨表示」（根拠・委任・準用の別の推定は Stage C 以降）
- 別表表題の条参照（§13.1 記載、別途検討）

### 14.4 受入測定

- 2,380ノードの明示参照に対する解決率（方向別に計測）
- 既知の対応（法第20条 → 施行令第36条系等）の目視確認
- 逆引き一覧が上位条文ブロックに表示され、リンクが新しいタブで開くこと
