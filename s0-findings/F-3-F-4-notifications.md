## F-3: 告示の取得可能性

### 掲載形式（実測）

当該ページのリンク 244 本のうち **233 本が PDF**、HTML は 5 本（ページ内リンク）のみ。**告示本文の HTML 版は存在しない。**

### PDF の種別: テキストPDF（OCR 不要）

3件を取得して抽出を試みた。

| ファイル | ページ | 抽出文字数 | 日本語比率 |
|---|---|---|---|
| 令和8年国交省告示第438号 | 5 | 2,544 | 89% |
| 令和8年国交省告示第693号 | 8 | 4,230 | 91% |
| 令和8年厚労省・国交省・環境省告示第2号 | 1 | 209 | 90% |

**画像 PDF ではない。** 設計書 §8.4 が「最高難度」としていた OCR 処理は、少なくとも近年の告示では不要である。これは F-3 にとって大きな追い風である。

### 抽出時の課題（いずれも正規化で対応可能）

1. **文字間に空白が入る。** 縦書きレイアウトのため 1 文字ごとに空白が挟まる

```
抽出結果   ○ 国 土 交 通 省 告 示 第 四 百 三 十 八 号
正規化後   ○国土交通省告示第四百三十八号
```

2. ページヘッダ（`- 1/5 -`）が本文に混入する。除去が必要

### 告示番号と根拠条項は本文冒頭から取得できる

```
○国土交通省告示第四百三十八号
建築基準法（昭和二十五年法律第二百一号）第十八条の三第一項の規定に基づき…
```

告示番号、根拠法令、根拠条項がいずれも冒頭に定型で現れる。**F-6 の Citation Resolver をそのまま適用して根拠条項を解決できる。** 設計書 §7.2 の `DELEGATES_TO` エッジ（法→告示の委任）を機械的に張れる見込みがある。

## F-4: 溶け込み実現性 — **公式の現行全文は存在しない**

### 掲載されているもの

国土交通省のページに掲載されるのは次の3種である。

| 種別 | 内容 | 設計書 §5.2 の Consolidation State |
|---|---|---|
| **案文** | 公布時の制定本文 | `OFFICIAL_AS_ENACTED` |
| **新旧対照表** | 改正部分のみの対照 | `OFFICIAL_AMENDMENT` |
| 技術的助言 / 事務連絡 | 解釈・運用の通知 | `OFFICIAL_GUIDANCE` |

**`OFFICIAL_CONSOLIDATED`（溶け込み済み現行全文）に相当するものは掲載されていない。**

ページは「公布日ごとの改正イベントの履歴」であり、「現行の告示集」ではない。ある告示の現在有効な全文を知るには、制定時の案文に対して、その後のすべての改正を利用者自身が適用する必要がある。

### 自製統合のコストは高い

1つの改正告示が多数の既存告示を同時に改正する。実例として令和6年国土交通省告示第221号は次を改正している。

```
昭和48年建設省告示第2565号（防火区画を貫通する風道の防火設備）
平成12年建設省告示第1436号（排煙設備の設置を要しない建築物の部分）
平成26年国土交通省告示第255号（特殊建築物の主要構造部）
平成28年国土交通省告示第695号
令和元年国土交通省告示第193号
令和元年国土交通省告示第194号
… 他28件の一部改正
```

**1つの改正で 34 件以上の告示が改正される。** 対象告示 15〜20 件（Solo Track のスコープ）を現行化するには、それぞれについて制定時からの全改正を追跡して適用する必要がある。

設計書 §15.9.1 の S0 中止条件は「告示の統合が1件あたり2時間を超える」であるが、**この構造では 2 時間で収まらない告示が相当数あると見込まれる。**

### 公式掲載物にも誤りがある（設計を裏付ける実例）

ページ上に次の注記が実在する。

> 本ページに掲載の案文は誤りを修正した後のもの。近日中に官報正誤にて対応予定。

> 案文に一部誤りがあったため、再度掲載いたしました。（令和６年10月11日付）

**公式サイトの掲載物ですら誤りがあり、後から差し替えられ、官報が優先する。** これは設計書 §5.2 が `verification_status` に `GAZETTE_VERIFIED`（官報照合済）を設けた判断と、§5.3 の「`DERIVED_CONSOLIDATED` を Primary Citation にできない」制約を強く正当化する。

同時に、§8.1 の取込パイプラインが Content Hash による差分検知を必須としている判断も裏付けられた。**同じ URL の PDF が予告なく差し替わる。**

## O-1 の判断材料

設計書 §15.2 の3択に対する現時点の評価である。**これは設計判断ではなく事業判断であり、決定は Taguchi さんに委ねる。**

| 案 | 内容 | 評価 |
|---|---|---|
| **A** | 自製の編集現行版を人手確認込みで提供する | 価値は最大。ただし Solo Track の工数を確実に超える。告示15〜20件でも、制定時からの全改正追跡が必要。Domain Reviewer の確認工数も跳ね上がる |
| **B** | 告示は原文（案文＋新旧対照表）のみ提供し、統合は利用者に委ねる | 実装は現実的。「どの改正がこの告示に掛かっているか」を漏れなく一覧できるだけでも、現状の手作業より価値がある。ただし「現行条文が読める」という期待には応えられない |
| **C** | 対象テーマを告示依存の少ない領域へ変更する | 防火・避難は告示依存が最も強い領域であり、テーマ変更の効果は大きい。ただし調査頻度の高さという当初の選定理由を失う |

### 現時点の私見

**B を基本に、A を限定適用する案**を推奨する。

告示を「現行全文」として提供することは諦め、次の形にする。

1. 告示の**案文（制定時本文）を `OFFICIAL_AS_ENACTED` として収録する**
2. その告示に掛かるすべての改正を、**改正履歴の一覧として時系列で提示する**（新旧対照表へのリンク付き）
3. 「この告示には公布後 N 件の改正があります。現行全文は本サービスでは提供していません」と明示する
4. 需要が確認できた数件だけ、人手確認込みで `DERIVED_CONSOLIDATED` を作る

この形なら、設計書 §5 の Consolidation State モデルがそのまま活き、**誤った現行全文を自信を持って表示するリスクを負わない**。設計書 §18 の最重要原則とも整合する。

一方で、これは「紙の法令集の代替」という当初の価値提案からは後退する。**U-1（実務者ヒアリング）で「告示の現行全文が読めないツールに価値があるか」を必ず確認する必要がある。**
