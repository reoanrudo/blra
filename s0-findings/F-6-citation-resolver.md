### 解決率の定義

実コーパスの本則条文から抽出した明示的引用のうち、参照先の `canonical_path` が同一法令内に実在する割合。コーパス側に正解（実在する path 集合）があるため自己検証できる。

他法令への参照と相対参照は、この方法では正誤を判定できないため分母から除いている。

## 設計書への反映が必要な発見（2件）

### 発見1: 項を省略した号参照の補完が必須（要・設計書追記）

**当初 71.0% だった施行令の解決率が、この補完で 98.9% に上がった。**

法令では、条に項が1つしかない場合に項番号を省略して「第二条第九号」と書く。しかし構造上は第1項の第九号であり、実コーパスの `canonical_path` は次である。

```
引用の字面      第二条第九号
実際のパス      art2/para1/item9
素朴な変換      art2/item9        ← 存在しない
```

`art2/item9` は実コーパスに存在せず、素朴に変換すると参照が解決できない。

**対応**: `item` があって `para` がない引用は、`art{n}/para1/item{m}` を第1候補、`art{n}/item{m}` を代替候補として返す。`CitationRef.alternatePaths` を追加した。

同様に、条のみの参照（「第三十五条」）も `art35` と `art35/para1` の両方を候補とする。

→ **設計書 §6.3 の `CitationRef` に `alternatePaths` を追加し、この慣行を明記すべき。** Reference Edge（§7）の解決でも同じ処理が要る。

### 発見2: 略称「法」「令」の解決先は、読んでいる法令に依存する

施行令の条文中の「法第二条」は建築基準法を指し、施行令自身ではない。当初この区別をせず、施行令の「法第○条」を施行令内の path として検証していたため、解決率を実態より低く測っていた。

| 読んでいる法令 | 「法」 | 「令」 |
|---|---|---|
| 建築基準法 | 自身 | 施行令 |
| 建築基準法施行令 | 建築基準法 | 自身 |
| 建築基準法施行規則 | 建築基準法 | 施行令 |

設計書 §6.3 は「略称は context なしには解決できない」と既に述べているが、**context として必要なのは「現在の法令 ID」だけでなく「その法令の種別（法/政令/省令）」である**。略称辞書は法令種別ごとに持つ必要がある。

## 残課題

未解決の 3 件（全体の 0.13%）は、いずれも建築基準法第2条第1項第17号（「設計図書」の定義）から**建築士法**の条文を参照するものである。

```
第二十条の三第二項  → art20-3/para2（建築基準法には存在しない）
第十条の三第四項    → art10-3/para4（同上）
```

法令名の検出ウィンドウを直前40文字としているため、離れた位置にある「建築士法」を取り逃している。**参照先を誤った法令内で解決することは、設計書 §18 の最重要原則に反する誤りである**ため、本実装では次のいずれかが必要になる。

- 法令名の検出ウィンドウを文単位へ広げる
- 解決先が現在の法令に存在しない場合、他法令への参照とみなして `unresolved` にする（設計書 §7.3 の「参照先が本サービスに未収録です」表示へ回す）

**後者を推奨する。** 存在しない path へ自信を持ってリンクするより、未解決と表示するほうが安全である。

## 追加発見（2026-07-29・市販法令集の誌面 OCR から）

`docs/reference/hourei-shu-2026-ocr.md` の表記方法一覧に載る実務の略記を、現行の Resolver へ通した結果、**3件の欠陥**が出た。

### 欠陥1（重大）: 号の枝番が黙って切り捨てられる

```
入力  都市計画法第八条第一項第四号の二の規定により
出力  art8/para1/item4          ← 「の二」が消えている
```

**第四号と第四号の二は別の規定である。** 現行の `EXPLICIT_RE` は `第(NUM)号` までしか見ておらず、`号の二` を取りこぼしたうえで、切り捨てた結果を confidence 0.7〜0.95 で返す。

これは設計書 §18 の最重要原則（誤った条文を自信を持って表示しない）に正面から反する。**silent truncation は未解決より悪い。**

同様の例:

```
入力  法第二条第九号の二イに規定する
出力  art2/para1/item9          ← 「の二イ」が消えている
```

号の下の「イロハ」階層も未対応である。

**S1 での対応方針**: 号の枝番（`号の二`）とイロハ階層を `EXPLICIT_RE` に追加する。パースできない枝番を検出した場合は、切り捨てた path を返さず `unresolved` とする。

### 欠陥2: 法令の略称が検索クエリで解決できない

```
"建基法63条"        → 解決できず
"都計法8条1項四号の二" → 解決できず
```

`parseQuery` の法令名リストが「建築基準法／施行令／施行規則／法／令／規則」に限られている。実務者は「建基法」「都計法」を日常的に使う（市販法令集が略称一覧として28件を定義しているのが証左）。

**S1 での対応方針**: 略称辞書を運用データとして持つ。初期値は `docs/reference/hourei-shu-2026-ocr.md` §2.6 の28件を自力で整備し直したものを使う（出版社の一覧は照合用であり転載しない）。

### 欠陥3: 「号」は漢数字のままである

市販法令集の表記方法(1)は、漢数字を算用数字化する対象から**「第一種、一級といった『区分』、法令中の『号』等を除く」**と明記している。実際の略記も `都計法8条1項四号の二` と、条・項は算用数字、号だけ漢数字である。

現行の Resolver は号も算用数字へ正規化しており、**実務者の書き方と一致しない**。検索クエリの解釈では両方を受け付け、表示では法令の慣行（号は漢数字）に合わせる必要がある。

### 検証できた点

```
"法2条"            → art2 (alt: art2/para1)     OK
"規則4条の20第2項"  → art4-20/para2              OK
"法35条の3"        → art35-3 (alt: art35-3/para1) OK
"第五十二条の二第一項第三号" → art52-2/para1/item3  OK
```

条の枝番、算用数字と漢数字の混在、項号の組み合わせは正しく解決している。**欠陥は号の枝番と略称に限定される。**
