# F-9: 履歴版の遡及範囲実測 — 結果

- 実施日: 2026-07-29
- 目的: 各 Source の `coverage_from`（設計書 §4.6）初期値を確定する
- 判定: **重大な制約を確認。プロダクト判断が必要**

## 実測結果

e-Gov 法令API v2 `/api/2/law_revisions/{law_id}` で取得できる全版を集計した。

| 法令 | 公布日 | 提供版数 | **取得可能な最古の施行日** | 最新 |
|---|---|---|---|---|
| 建築基準法 | 1950-05-24 | 38 | **2016-09-01** | 2027-05-26 |
| 建築基準法施行令 | 1950-11-16 | 27 | **2017-04-01** | 2025-12-01 |
| 建築基準法施行規則 | 1950-11-16 | 50 | **2017-04-01** | 2026-04-01 |

つまり `coverage_from` は次のとおりとなる。

```
建築基準法      coverage_from = 2016-09-01
施行令          coverage_from = 2017-04-01
施行規則        coverage_from = 2017-04-01
```

**公布から約66年分の履歴は、e-Gov API からは取得できない。**

## プロダクトへの影響

設計書 §4.3 は適用時点アンカーとして `EXISTING_BUILDING_ORIGIN`（既存建物の建築時点）を定義している。しかし既存不適格（建築基準法第3条第2項）が問題になる建物は、定義上、規制強化より前に建てられたものである。**その大半は 2016年より前であり、当該時点の条文を本サービスでは表示できない。**

現状の設計（§4.6・ADR-019）では、この場合の応答は次になる。

```
指定された日付（1998-04-01）の条文は本サービスの収録範囲外です。
収録している最古の版は 2016-09-01 施行版です。
```

これは誤った条文を表示するよりはるかに良い。設計書 §18 の最重要原則にも合致する。しかし、**`EXISTING_BUILDING_ORIGIN` アンカーは実務案件の大半で機能しない**ことになる。

## 判断が必要な選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| A | 収録範囲外を正直に返し、`EXISTING_BUILDING_ORIGIN` は「起点日の記録」機能に留める（条文表示はしない） | 追加コストなし。設計変更は小。ただし既存不適格の調査価値は提供できない |
| B | 別ソースから過去版を補う（官報アーカイブ、国立国会図書館デジタルコレクション、加除式法令集） | 価値は高いが、取得・構造化・権利処理のコストが Solo Track の想定を超える可能性が高い |
| C | MVP の対象テーマから既存不適格を明示的に外し、新築案件に絞る | S0 での対象テーマ確定（O-3）と整合させやすい |

**現時点の推奨は A ＋ C の併用**である。`EXISTING_BUILDING_ORIGIN` アンカーは残すが（日付の記録と、その日以降の改正一覧の提示には使える）、当該時点の条文表示は約束しない。対象テーマは新築の防火・避難に寄せる。

ただしこれは U-1（実務者ヒアリング）の結果次第で変わる。既存不適格の調査が上位課題に入るなら、案 B の実現可能性を別途調べる必要がある。

→ **O-3（対象テーマの確定）と合わせて S0 Exit で決定する。**

## 副次的な確認

- `amendment_scheduled_enforcement_date` が別項目として存在する。設計書 §4.2 の `valid_from_status = UNDETERMINED`（「政令で定める日から施行する」）を API 側の情報で判定できる見込みがある。ただし実際にこの値が入る版を本コーパスでまだ観測していない
- 建築基準法には施行日 2027-05-26 の未施行版が既に存在する。設計書 §4.2 の「未施行版は検索結果に含めず、条文表示画面で別枠表示する」の動作確認に使える実データがある
