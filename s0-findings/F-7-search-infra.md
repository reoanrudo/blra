# F-7: 検索基盤と拡張の可用性確認 — 結果

- 実施日: 2026-07-29
- 対象の未解決事項: O-2（日本語検索基盤）、M-1（btree_gist）
- 判定: **PASS。pg_bigm を採用し、OpenSearch は導入しない**
- 再現: `psql -d blra_f7 -f spikes/sql/f7-constraints.sql` / `npm run f7:export` → `psql -d blra_f7 -f spikes/sql/f7-search.sql`

## 1. 拡張の可用性（PostgreSQL 16.13 / Homebrew）

| 拡張 | 版 | 用途 | 結果 |
|---|---|---|---|
| `btree_gist` | 1.7 | EXCLUDE 制約での uuid 等値比較（ADR-013） | **利用可** |
| `pg_bigm` | 1.2 | 日本語 N-gram 全文検索（§9.2） | **利用可** |
| `pg_trgm` | 1.6 | 3-gram。日本語には不利 | 利用可 |
| `pgroonga` | — | 形態素＋N-gram | **利用不可** |

`pgroonga` は Homebrew の PostgreSQL 16 に含まれない。ただし後述のとおり `pg_bigm` で要件を満たせるため、支障はない。

## 2. 設計書 §13.1 の制約が実機で機能するかの検証

`spikes/sql/f7-constraints.sql` で7ケースを実行し、**全て期待どおりの結果**を得た。

| # | ケース | 期待 | 結果 |
|---|---|---|---|
| 1 | FIXED かつ `valid_from` あり | 成功 | 成功 |
| 2 | FIXED かつ `valid_from` が NULL | CHECK で拒否 | **拒否**（`provision_version_check`） |
| 3 | UNDETERMINED かつ `valid_from` が NULL | 成功 | **成功** |
| 4 | 同一 provision で期間が重複 | EXCLUDE で拒否 | **拒否**（`no_overlapping_validity`） |
| 5 | `valid_to` = 次の `valid_from`（半開区間の境界） | 成功 | 成功 |
| 6 | 別 provision で同一期間 | 成功 | 成功 |
| 7 | 現行版が2つ（`valid_to` NULL が重複） | EXCLUDE で拒否 | **拒否** |

**確認できたこと。**

- **C-1 の修正は正しい。** ケース2とケース3の対比により、「政令で定める日から施行する」を仮日付なしで表現でき、かつ FIXED での NULL 混入は DB が拒否する。当初の `NOT NULL` のままでは、この2つを同時に満たせなかった
- **ADR-013 は機能する。** ケース7が特に重要である。「現行版が2つ存在する」というコーパス最悪の不整合を、アプリのバグに関係なく DB が拒否する
- **半開区間 `[valid_from, valid_to)` の運用は正しい。** ケース5で隣接する版が境界日を共有しても衝突しない

時点解決クエリ（§4.2）も、2025-06-01 時点で正しく1件のみを返した。

## 3. pg_bigm による日本語検索の実測

実コーパス 6,552 条項（建築基準法 2,241 / 施行令 2,526 / 施行規則 1,785）を投入して測定した。

### 索引と性能

`gin (body gin_bigm_ops)` を作成し、`EXPLAIN` で **Bitmap Index Scan on idx_body_bigm** が選択されることを確認した。

| クエリ | 応答時間 |
|---|---|
| `body LIKE '%特定防火設備%'` | 15.2 ms |
| `body LIKE '%防火区画%'` | 1.0 ms |

設計書 §14.1 の目標（検索 P95 2秒以内）に対して桁違いの余裕がある。

### 専門語のヒット数

| 語 | 件数 |
|---|---|
| 準耐火構造 | 45 |
| 排煙設備 | 33 |
| 特定防火設備 | 31 |
| 防火区画 | 20 |
| 避難階段 | 19 |
| 竪穴 | 11 |
| **無窓居室** | **0** |

形態素解析の辞書に依存しないため、複合専門語がそのまま引ける。設計書 §9.2 の懸念（「形態素単独では取りこぼす」）は、N-gram を採ることで回避できる。

## 4. 判断

> **O-2 の決定: pg_bigm を採用する。OpenSearch を導入しない。**

理由は次のとおり。

- 性能に大きな余裕がある（1〜15 ms / 6,552 条項）
- 専門語の取りこぼしがない
- インフラが1つ減る。Solo Track（§15.8）では運用対象を増やさないことの価値が大きい
- 設計書 §9.2 が挙げた移行条件（ランキング要件を満たせない、Index 量または Query 量が DB を圧迫、Facet/Highlight/Synonym の運用が複雑化）に、現時点で該当しない

**ただし ADR 化の前に確認が必要な事項が1つある。** 上記はローカルの Homebrew PostgreSQL での結果である。デプロイ先のマネージド PostgreSQL（設計書 §13.3）で `pg_bigm` と `btree_gist` が使えるかは未確認である。`btree_gist` は contrib の標準構成であり大半のサービスで使えると見込まれるが、`pg_bigm` はサードパーティ拡張であり、提供されないサービスがある。

→ **S1 のインフラ選定時に、候補サービスでの拡張可否を確認してから ADR を確定する。** 使えない場合の代替は、コンテナで PostgreSQL を自前運用するか、OpenSearch へ切り替えるかの二択になる。

## 5. 副産物: 現場用語と法令用語の乖離を実測

「無窓居室」が **0 件**であった。法令上の表記は次である。

```
建築基準法 第35条の3
  政令で定める窓その他の開口部を有しない居室は、その居室を区画する
  主要構造部を耐火構造とし、又は不燃材料で造らなければならない。
```

実務では「無窓居室」と呼ぶが、条文には「窓その他の開口部を有しない居室」としか書かれていない。**検索語をそのまま投げても1件も出ない。**

これは設計書 §1.1 が挙げた課題「現場用語と法令用語が一致しない」の実例であり、§9.3 の同義語辞書が任意の改善ではなく必須機能であることを示す。

同義語辞書の初期エントリとして記録する。

| 実務語 | 法令上の表記 |
|---|---|
| 無窓居室 | 窓その他の開口部を有しない居室 |

U-3（検索課題30件の収集）では、実務者が使う語をそのまま集め、法令表記との対応を Domain Reviewer に確認してもらう必要がある。この対応表が検索品質を直接決める。
